# M9.5 Co-op Soak Runbook (two machines, one hour)

The Networked Co-op Slice acceptance run: two players over the internet on
packaged M9 builds - traverse the greybox world, see each other move, fight,
disconnect/reconnect cleanly - for one hour without desync, leak, or crash.
No cargo, no editor, no source checkout on the test machines.

Roles: **host** (has this repo + spacetime CLI, publishes) and **friend**
(receives a zip, runs an exe). One machine can play both roles for a dry
run - then launch the two clients with distinct `--net-id` slots.

## 1. Host: publish to Maincloud

```powershell
spacetime login show          # expect an identity; otherwise: spacetime login
./server/publish.ps1 -Server maincloud -Module nstoilov-rust-engine
```

- Module names on Maincloud are global to the account/namespace.
- The publish must end with the `set_build_id` call succeeding. Verify:

```powershell
spacetime sql --server maincloud nstoilov-rust-engine "select protocol_version, build_id from config"
```

`protocol_version` must be the current `PROTOCOL_VERSION`
(`game_shared/src/net/schema.rs`) and `build_id` must equal
`git rev-parse --short HEAD` (+`-dirty` if the tree was dirty). If the
stamp is stale the clients will warn on connect ("build mismatch") - fix
before distributing bundles. Note the stamp only succeeds for the identity
that first published (owner-gated); publishing from another account's CLI
will warn `set_build_id call failed`.

- Schema changed since the last publish (new tables/columns)? Add `-Wipe`.
  Protocol bumps always require it.

## 2. Host: export + distribute the client bundle

```powershell
./scripts/export_windows.ps1 -OutputDir build/export-mp -Target mp-client `
    -ServerUri https://maincloud.spacetimedb.com -Module nstoilov-rust-engine
```

Same tree as the publish (same commit + dirty state), or clients will show
the build-mismatch warning. Zip `build/export-mp/` and send it to the
friend. The bundle auto-connects on launch (`net_config.ron`,
`auto_connect: true`); no CLI args needed. To repoint later, edit
`net_config.ron` next to the exe - no rebuild.

## 3. Both: run

Each player, in the unzipped folder:

```powershell
./game.exe                                   # auto-connects via net_config.ron
```

In a second terminal, start the leak monitor (copy `scripts/soak_monitor.ps1`
into the bundle zip, or run it from the repo checkout on the host):

```powershell
powershell -File soak_monitor.ps1 -IntervalSec 30 -OutCsv soak_<name>.csv
```

Same-machine dry run only: `./game.exe --net-id a` and `./game.exe --net-id b`
(distinct identity slots; without them the second launch replaces the first
session instead of adding a second player).

## 4. The hour: checklist

Do all of these at least once; keep both clients running the whole hour.

- [ ] Both players visible to each other; movement is smooth (M6
      prediction, no rubber-banding at rest)
- [ ] Traverse the greybox world together: gym slopes/steps and at least
      one far zone (streams in/out on both screens) (M3/M4)
- [ ] Fight mobs; fight each other with abilities; at least one death +
      respawn each (M7)
- [ ] Projectiles visibly consistent on both screens
- [ ] One player quits (clean close) and rejoins: no ghost on the other's
      screen while away, rejoin works, no duplicate player (M5)
- [ ] One player hard-kills the exe (Task Manager) and rejoins: same
      cleanliness bar
- [ ] End of hour: no crash on either machine; both `soak_*.csv` show
      flat-ish working set (no monotonic climb); no desync noticed
      (positions/combat agreed on both screens)

## 5. If something goes wrong: capture

- Client stdout: run `./game.exe > client.log 2>&1` on the next attempt
  (markers: `net: connecting`, `net: in world as`, `net: local player
  bound to entity`, `net: disconnected:`)
- The `soak_*.csv` files from both machines
- Server logs + state (host; admin commands need explicit `--server`):

```powershell
spacetime logs --server maincloud nstoilov-rust-engine -n 2000 > server.log
spacetime sql  --server maincloud nstoilov-rust-engine "select entity_id, session from player"
```

- Energy/usage: https://spacetimedb.com/nstoilov-rust-engine (dashboard)

Record the outcome (date, duration, checklist result, artifacts) in
`VULKANO-M9.5-COOP-VERIFICATION.md` under Status.

## Variant: self-hosted server instead of Maincloud

Rent a VPS, install the spacetime CLI, run `spacetime start` behind an open
port (default 3000; put TLS/a reverse proxy in front for anything beyond a
quick test). Then everywhere above replace `--server maincloud` /
`https://maincloud.spacetimedb.com` with `http(s)://<host>:<port>`. Not
implemented or tested in M9.5 - Maincloud is the supported path.
